# 项目现状与本阶段小结

> 最后核对：2026-09-18 ｜ 代码状态：`main`，v1.0

## 它是做什么的

浙大玉泉校区尼普顿电动自行车充电桩的实时空位面板。本地 `python monitor.py` 起在 <http://127.0.0.1:8000>，线上版在 <https://neptune-charger-monitor.vercel.app>（推 `main` 自动部署）。

## 关键事实（均为实测/核对结果，不是估计）

| 项 | 现状 |
| --- | --- |
| 规模 | 14 个站点、35 台设备、420 个插座（每台 12 孔） |
| 坐标系 | 上游接口与 `stations_yuquan.csv` 都是 **BD-09**；面板按用途换算（高德→GCJ-02，百度→BD-09，浏览器定位 WGS-84→BD-09） |
| 站点位置精度 | 约 **45 m**（以 OSM 同名建筑为独立参照，8 对平均残差） |
| 更新节奏 | 本地后台每 20 s 抓取；面板每 15 s 拉取；后台标签暂停 |
| 上游稳定性 | 偶发单台超时或 502（一轮 35 台中 0~2 台）；**冷启动第一轮几乎总有 1~3 台失败**，随后轮次恢复 |
| 数据实时性 | 实测 35 秒内 2 台设备状态发生变化 |

## 怎么复核

```powershell
python monitor.py                                  # 启动，浏览器开 http://127.0.0.1:8000
curl -s http://127.0.0.1:8000/api/status | head -c 300   # 接口异常时先单点确认
```

- 坐标是否仍然正确：按 [坐标与位置核对](./coordinates.md) 第 4 节的方法，用 OSM 同名建筑比残差。
- 重新截图（写 README 用）：

```powershell
npx playwright screenshot --channel msedge --viewport-size=1100,900 --full-page `
  --wait-for-timeout=4000 http://127.0.0.1:8000/ out.png
```

> 注意：上游偶发失败，直接截容易拍到「部分设备暂时取不到数据」的降级状态；`docs/images/` 里的截图是等一次完整轮询（35/35、420 孔）后再拍的。
