## 2. 校园地图文件不能当作坐标使用（已核对）

`docs/reference/yuquan-charging-points-map.json` 里**没有每个点的经纬度**——只有 960×609 底图上的像素锚点 `image_anchor.pixel`，外加一个「校区级」参考点（文件自己也注明 `not a coordinate for each charging point`）。

更关键的是：这张底图**不是按比例绘制的示意图**，所以像素锚点换算不出可用坐标。

证据（用我们已核对的站点坐标作基准配对）：

- 取 10 个名称无歧义的站点，共 45 对，`像素距离 / 实际距离` 落在 **0.73 ~ 3.37 米/像素**，相差 **4.6 倍**；用全部 14 站则是 0.41 ~ 5.57，相差 13.7 倍。地图若按比例，这个比值应当恒定。
- 单应（透视）模型并不比仿射好（平均残差 104.9 m vs 103.2 m），说明不是「斜着拍的照片」，而是示意图。
- 即便强行拟合，14 点平均残差约 **105 m**、最大约 **350 m**，明显差于我们现有坐标（约 45 m）。
- 方位角也对不上：例如「教十 → 原电工厂」图上 68.8°、实际 12.2°，差 56.6°。

**结论：不要用这个文件去改站点坐标。** 我们的坐标来自上游接口，精度更好。

## 4. 该参考点的坐标系是 GCJ-02（不是我们用的 BD-09）

文件里唯一的经纬度是 `source.campus_reference_coordinate` = `120.122946, 30.263776`。

- 与「14 个站点质心」的 **GCJ-02** 表示相差 **144 m**
- 与同一质心的 **BD-09** / **WGS-84** 表示分别相差 **821 m** / **831 m**

所以它是 **GCJ-02**（多半是从高德类地图上读下来的）。这意味着同一个文件家族里混着两种坐标系：点位数据要用 BD-09，这个参考点是 GCJ-02，**混用会偏约 930 m**。目前该参考点没有被代码使用。

## 5. 位置上报：已做轻量版，聚合版暂缓

2026-09-18 决定：先做「本地自检 + 报错入口」，暂不做用户上报聚合。

**已实现（`static/index.html`）**

- 定位后每张站点卡显示「你当前位置距本站约 xx 米」；若你在某站点 200 米内，页面直接提示你似乎就在哪个站点旁边。
- 站点卡提供「登记位置有误？上报」，点开是预填好的 GitHub issue：含站点在 BD-09 / GCJ-02 / WGS-84 下的登记值、本次定位（BD-09 与浏览器原始 WGS-84）、定位精度、时间。
- 位置不落库、页面不自行发送；**只有用户主动点链接才会发出，且 issue 是公开的**。

**为什么暂缓「匿名上报 + 后端聚合」**

- 站点坐标已准到约 45 米，剩余不确定只有生仪楼一站，一次现场核对即可解决。
- 精度账不划算：手机 GPS 在楼宇间误差常 30~100 米，要把定位压到 5 米量级每站需几十次上报；且用户标记的是自己站位（常在楼门口）而非桩位，存在系统性偏移，样本再多也不会消失。
- 代价：需引入数据库（Vercel KV 等）、修改隐私说明、加防滥用与人工审核。

**什么时候值得做完整版**：同一站点累积到一定量彼此一致的上报时（例如 ≥10 条），再评估，并同步更新隐私说明。
